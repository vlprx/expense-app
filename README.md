# Expense App

RESTful API для управління користувачами, категоріями та витратами з використанням Flask і PostgreSQL.

## Використані технології

- Python 3.13
- Flask 3.1.3
- PostgreSQL 16
- Flask-SQLAlchemy
- SQLAlchemy ORM
- Flask-Migrate
- Alembic
- Marshmallow
- Docker
- Docker Compose
- GitHub Actions
- Ruff
- Bruno

- Python 3.13

## Запуск застосунку

Клонуйте репозиторій:

```bash
git clone https://github.com/vlprx/expense-app.git
cd expense-app
```

Зберіть Docker-образи та запустіть контейнери:

```bash
docker compose up --build -d
```

Перевірте стан контейнерів:

```bash
docker compose ps
```

Застосуйте міграції бази даних:

```bash
docker compose exec web flask --app run.py db upgrade
```

Після запуску API доступне за адресою:

```text
http://localhost:5000
```

PostgreSQL використовує такі параметри підключення:

- Database: `expense_db`
- User: `expense_user`
- Password: `expense_password`
- Port: `5432`

Рядок підключення задається через змінну середовища `DATABASE_URL`.

## Моделі бази даних

Застосунок використовує такі ORM-моделі:

### User

Представляє користувача системи.

Поля:
- `id` — ідентифікатор користувача.
- `name` — ім'я користувача.

### Category

Представляє категорію витрат.

Поля:
- `id` — ідентифікатор категорії.
- `name` — назва категорії.

### Account

Представляє фінансовий рахунок користувача.

Поля:
- `id` — ідентифікатор рахунку.
- `user_id` — ідентифікатор власника рахунку.
- `balance` — поточний баланс.

Для кожного користувача автоматично створюється один рахунок.

### Record

Представляє запис про витрату.

Поля:
- `id` — ідентифікатор запису.
- `user_id` — ідентифікатор користувача.
- `category_id` — ідентифікатор категорії.
- `created_at` — дата та час створення запису.
- `amount` — сума витрати.

Між моделями налаштовані зв'язки, зовнішні ключі та каскадне видалення пов'язаних записів.

## Міграції бази даних

Для керування змінами структури бази даних використовується Alembic через Flask-Migrate.

Створення нової міграції:

```bash
flask --app run.py db migrate -m "Migration description"
```

Застосування міграцій:

```bash
flask --app run.py db upgrade
```

Перегляд поточної версії міграції:

```bash
flask --app run.py db current
```

Історія міграцій зберігається в директорії `migrations/versions/`.

## REST API

### Перевірка стану застосунку

| Метод | Маршрут | Опис |
|---|---|---|
| GET | `/healthz/live` | Перевірка працездатності застосунку |
| GET | `/healthz/ready` | Перевірка підключення до PostgreSQL |

### Користувачі

| Метод | Маршрут | Опис |
|---|---|---|
| GET | `/users` | Отримання всіх користувачів |
| GET | `/user/{user_id}` | Отримання користувача |
| POST | `/user` | Створення користувача |
| DELETE | `/user/{user_id}` | Видалення користувача |

Під час створення користувача автоматично створюється рахунок із початковим балансом `0.00`.

Приклад запиту:

```json
{
  "name": "Valeriia"
}
```

### Категорії

| Метод | Маршрут | Опис |
|---|---|---|
| GET | `/category` | Отримання всіх категорій |
| POST | `/category` | Створення категорії |
| DELETE | `/category/{category_id}` | Видалення категорії |

Приклад запиту:

```json
{
  "name": "Food"
}
```

### Рахунки

| Метод | Маршрут | Опис |
|---|---|---|
| GET | `/account/{user_id}` | Отримання рахунку користувача |
| POST | `/account/{user_id}/deposit` | Поповнення рахунку |

Приклад запиту на поповнення:

```json
{
  "amount": "200.00"
}
```

### Витрати

| Метод | Маршрут | Опис |
|---|---|---|
| POST | `/record` | Створення запису про витрату |
| GET | `/record/{record_id}` | Отримання окремого запису |
| GET | `/record?user_id=1` | Фільтрація за користувачем |
| GET | `/record?category_id=1` | Фільтрація за категорією |
| DELETE | `/record/{record_id}` | Видалення запису |

Приклад створення витрати:

```json
{
  "user_id": 1,
  "category_id": 1,
  "amount": "25.50"
}
```

## Валідація даних

Для перевірки вхідних JSON-даних використовується Marshmallow.

Перевіряються:
- обов'язкові поля;
- типи даних;
- допустима довжина текстових значень;
- додатне значення суми;
- наявність користувача та категорії.

У разі некоректних даних API повертає HTTP 400 із повідомленням про помилку валідації.

## Індивідуальне завдання

Номер у списку групи: **17**.

Розрахунок індивідуального варіанта:

```text
V = (N % 3) + 1
V = (17 % 3) + 1
V = 2 + 1
V = 3
```

Обраний варіант: **№3 — Account**.

Відповідно до індивідуального завдання реалізовано сутність `Account` із такими атрибутами:

- `id`
- `user_id`
- `balance`

Реалізовано такі бізнес-операції:

1. Автоматичне створення рахунку під час створення користувача.
2. Поповнення рахунку через `POST /account/{user_id}/deposit`.
3. Перегляд балансу через `GET /account/{user_id}`.
4. Автоматичне списання суми витрати з балансу під час створення запису.
5. Перевірка достатності коштів перед створенням витрати.
6. Відхилення операції, якщо коштів недостатньо.

Якщо баланс рахунку менший за суму витрати, API повертає HTTP 400 з помилкою `insufficient_funds`.

## Тестування API

Для документування та тестування запитів використовується Bruno.

Колекція запитів зберігається в директорії `bruno_collection/`.

Для перевірки роботи API можна використовувати Bruno або PowerShell.

Перевірка стану застосунку:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/healthz/ready
```

Перевірка рахунку:

```powershell
Invoke-RestMethod http://127.0.0.1:5000/account/1
```

## Автоматизація перевірок (CI Pipeline)

GitHub Actions автоматично запускає перевірки після надсилання змін (`push`) або створення запиту на злиття (`pull_request`) у відповідні гілки.

CI Pipeline включає:

1. Встановлення необхідних залежностей.
2. Статичний аналіз коду за допомогою Ruff.
3. Збирання Docker-образу.
4. Перевірку конфігурації Docker Compose.
